# 真机性能日志(BPMIK102080640200 / SpacemiT X60)

设备:SpacemiT X60(rv64imafdcv,RVV 1.0,VLEN=256,8 核),Bianbu Star 2.1,
内核 6.6.63。工具链:gcc 13.3(Ubuntu 24.04 交叉),`-O2 -march=rv64gcv`,
静态链接。测试:bench_e2e,4 秒信号,reps=5 取最优;定点构建。

> 注:A=src(工作副本),B=baseline(参照)。同轮 A/B 间存在 ~5% 级测量
> 噪声(A 恒略快于 B,疑似顺序/热效应);结论以 A 列跨轮对比为准,
> 小于 ~8% 的差异不作为结论依据。

## 第 7 轮(2026-11-03):真机剖析(无新内核)

板上无 perf 且 apt 源缺包,落地了 `-finstrument-functions` 剖析器:
`SPEEX_PROF=ON` 构建(测试/prof.c,rdtime 计时,退出时打印每函数
ticks),`nm` 符号化,`BENCH_PHASE=enc|dec` 分相位。修正符号化后
(rdtime 版,注意含插桩开销):

- **NB 编码**:pitch_search_3tap 子树 48%(内含 pitch_gain_search_3tap
  39%、其 _vq 19%),open_loop 39%,split_cb_search 11% —— 其余为
  已优化的 vq/inner_prod/pitch_xcorr。
- **解码**:LSP↔LPC 变换链(lpc_to_lsp/lsp_to_lpc)与 multicomb 尾部
  各占 ~30-44%(含嵌套),iir/fir/filter_mem16 已优化后占比很小,
  qmf_synth 次之。

**收敛结论(证据版)**:剩余热点由几十个 1-5K tick 的微小顺序/数值
循环构成(LSP 根查找的 bisect+acos、多项式级联展开、multicomb 逐元素
尾部),单点向量化预期 ≤5% e2e 且侵入最脆弱的数值代码。内核循环到此
收官;后续方向:①解码 LSP 变换链整体重写(跨系数 lane 并行,中风险);
②QMF 多相(跨输出样本 lane 并行,低风险小收益);③kiss_fft。

## 第 9 轮(2026-11-03,+ lsp_to_lpc 级联展开向量化)

按剖析数据实施"解码 27-29% 热点" lsp_to_lpc(MULT16_32_Q14 分裂乘法
逐元素向量化)。**真机 bit-exact ALL PASS,但 e2e 增益 ≈0**(各模式
解码与第 8 轮差异 <1%)。

**原因与教训**:剖析器 inclusive 计时把每函数的插桩钩子开销
(~1K ticks/调用)计入热点——lsp_to_lpc 每调用真实工作仅 ~150-400
ticks,"29% 占比"约九成是测量假象。**本剖析器对单次耗时低于 ~2K
ticks 的函数不可分辨**;这恰好证明所有剩余可测热点都已被吃干,
循环收敛的结论被反向证实。

期间 A/B 门还抓住一次真实语义误读:MULT16_32_Q14 的 >>14 只作用于
低半段乘积(a·hi + ((a·lo)>>14)),首版错写为 (a·hi + a·lo)>>14。

## 第 14 轮(2026-11-03,编码尾部清扫:open_loop/normalize16/gain 尾部/vq 向量尾部)

第 13 轮后重剖析(NB enc):open_loop_nbest_pitch 17%(pitch_xcorr 仅
占其 40%,其余为分支密集的 top-N 选择循环 + 能量递推 + scaledown 扫描)、
pitch_gain_search_3tap 自体 ~16%、split_cb 自体 ~10%(其中 vq_nbest
标量尾部比向量 raw_dists 还贵:WB 13.3% vs 5.8%)。

本轮 4 组内核:
- **open_loop_nbest_pitch 整体 override**:top-N 插入选择 ≡ "N 轮向量
  argmax + 逐轮剔除"(严格大于保先到、叉乘比值比较均可精确复刻,任意
  N 成立);能量递推保持标量滚动(C 每步有 clamp,非线性不可结合),
  仅向量化逐 lag 平方项;饱和扫描/恢复向量化(z/2^16 环上加法结合性
  论证见 rvv/ltp_rvv.h 头注)。
- **normalize16 override**(max-abs 扫描 vredmax + 标量移位决策)。
- **gain_search 尾部**:new_target 更新 + exc 重建逐元素向量化(源读
  全在负偏移,无读写重叠)。
- **vq_nbest/_sign N=1 向量尾部**:E 修正 + first-min argmin(逐 lane
  running + 标量树,无 red 链);N>1 保持标量插入。

**过程事故(本轮教训密度最高)**:
1. **基址重复偏移 bug**:`rvv_gain_build_exc` 第二段调用把"j=tmp1 处
   的地址"传给了"从 from 起算"的 src 形参,第二子段整体读错数据。
   qemu e2e 因缓存路径问题被跳过、prof-on 真机 A/B 又是旧二进制"假
   通过",最终靠**新写的专用差分测试在真机**抓出。教训:每个新内核
   必须有直接差分测试;prof-on/off 与构建成败必须显式确认。
2. **prof 污染口径**:-finstrument-functions 使调用密集路径虚高
   40-70%,prof-on 会话测出的 A/B 比值完全失真。**基准一律 prof-off**。
3. **构建失败被管道掩盖 + 陈旧二进制部署**:device-test.sh build 失败
   但 ab 照样 deploy 旧二进制,连续多轮"FAIL"实为陈旧产物。ab 前必须
   确认 build 成功输出。
4. **测试驱动窗口错位**:open_loop 差分测试把 RVV 调用写在与参考同一
   缓冲(sw 而非 sw2),SW-MISMATCH 风暴全是测试自身 bug。

**gcc-13 新踩坑(rvv-notes 同步)**:
- `vmerge_vvm(op1, op2, m)` = **m ? op2 : op1**——首参是 false 分支,
  与 RVV 规范(vd = v0 ? vs1 : vs2)相反(按汇编操作数序 vs2,vs1)。
- 掩码类型命名 = **vbool(SEW/LMUL)**:i32m2→vbool16_t,i16m2→vbool8_t。
- VARDECL 指针类型陷阱:`VARDECL(spx_word32_t *energy)` 展开成二级

## 第 28 轮(2026-11-12,P2 批转码并行落地)

**交付**:`benchmark/batch_parallel.c` —— 库外 pthread 批处理入口
(库内 API 零改动):K 个独立流、每流独立编码/解码器状态、条带分配
到 T 个工作线程;每轮并行结果与单线程参照**逐字节 memcmp 验证**,
并报告串行/并行墙钟加速比。

**X100 实测(交叉 gcc-14 构建,taskset -c 0-7 锁 8 大核,
performance governor;16 流 × 2s 与 32 流 × 5s 两组)**:

| 线程 | 编码加速 | 解码加速 |
|------|------|------|
| 2 | ×2.02-2.03 | ×2.00-2.04 |
| 4 | ×4.01-4.04 | ×3.64-4.10 |
| 8 | **×7.77-7.86** | ×6.78-**7.96** |

全部 bit-exact(每一档线程数、每一模式);长负载(1.4s 串行基线)
下扩展性更稳(8 线程 dec ×7.96)。近线性——P2 验收达成
(plan 预期 ×4-8)。

**踩坑( harness 侧,与库无关但值得记)**:
1. **libspeex 编码器会原地修改调用方的输入帧**(`highpass(in, in,
   ...)` 直写)——重复编码同一缓冲不是幂等操作,每轮必须从 pristine
   副本恢复;
2. 首版 decode pass 复用 worker 时误重编码,污染快照与工作缓冲——
   分相 worker(encode pass 才编码)后解决;
3. 定位过程:qemu 下 T=1 即发散(排除线程因素)→ 跨 pass 堆布局
   差异假设(排除,speex_alloc/scratch 均 calloc)→ 首帧即差、长度
   相同 → 逐层剥出原地突变。

**线程安全口径**:libspeex 编码/解码器实例间无共享可变状态
(mode 表为 const),每线程独立 state 即可安全并行;输出与线程数
无关(本工具即回归测试)。A100 簇维持不可达/不使用。

## 第 30 轮(2026-11-12,lsp_to_lpc 尾循环:伪串行链的向量化)

**发现**:lsp_to_lpc 的 ak 输出循环形似串行(携带 xout1/xout2),
但代入后 xout1/xout2 恰为上一迭代的 xp[m][j+1]/xq[m][j+1] ——
a[j] = ADD32(ADD32(xp[m][j+2], xp[m][j+1]), SUB32(xq[m][j+2],
xq[m][j+1])),是纯逐元素公式(i32 环绕下结合性成立)→ 整条"串行
链"可向量化。另把行循环里的 ap16/aq16 常量广播提出 chunk 循环。

**两次位精确事故(均被 A/B 门禁当场抓获,独立差分测试定位)**:
1. 代数符号:xout1 项是 **加** 不是减(A/B 全模式码流早段即差);
2. off-by-one:`off` 是 ak 下标减 1 而非 j,`xp[j+2]` 装载成了
   `xp[j+1]`,向量结果整体左移一帧——用独立差分测试(随机矩阵上
   并排运行参照循环与向量尾)暴露 new[j]==ref[j-1] 的移位模式;
3. 教训:**进程内调试钩子可能根本没执行**(dbg 构建 0 MISMATCH 与
   A/B 失败并存,排查浪费时间)——独立的可运行差分测试比进程内
   fprintf 钩子可靠;git stash 后续编辑会打在旧树上,先确认工作树
   状态。

**钳位顺序**:C 先钳位 ±32767 再转 short;先 vncvt 再钳位会把
超范围值回绕而不是钳位——i32 域钳位后截断。

**验收**:CTest 9/9;毒化 108/108;qemu A/B ALL PASS。X100 配对
(vs 第 29 轮):**dec +0.6~+1.1% 一致正收益,enc −1.5~+0.1%**
(布局噪声级)——净小幅为正,采纳;sp_to_lpc 残差进一步压缩空间
有限(行循环本体为真顺序递推)。

## 第 31 轮(2026-11-12,lsp_to_lpc 行循环:i64 精确积替代 hi/lo 模拟)

MULT16_32_Q14(a,b) 的向量模拟(hi/lo 拆分:1×vsra + 1×vand +
2×vncvt + 2×vwmacc + 1×vsra + 1×vadd ≈ 8 条)替换为 **i64 精确积
+ vnsra 一次窄化**(~3 条):ap*b 在 i64 无中间回绕,算术移位恒等式
((X·2¹⁴+Y)>>14 = X + (Y>>14)) 保证与 C 的 ADD32 形式 mod 2³² 同余
——即使 C 的中间量发生 i32 回绕也成立。vwmacc_vx_i64m4 直接吃
i32 向量操作数(内部符号扩展),无需显式加宽。

**验收**:CTest 9/9;毒化 108/108;qemu A/B ALL PASS。X100 配对
(vs 第 30 轮):**enc +0.6~+1.8%、dec +1.5~+2.5% 全线正收益**——
lsp_to_lpc 自身体(净环境剖析 ~10.6%)显著压缩。
